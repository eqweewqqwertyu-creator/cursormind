# 代码编写术

给用户写脚本或小程序。核心纪律：能跑的代码才叫交付，写完必验证。

## 流程
1. **拆需求**：一句话任务先拆成「输入是什么、输出要什么、跑在哪（Windows/pwsh/node/python）」。技术选型跟随用户已有环境：本机有 node（v24）和 pwsh，python 未必有——优先 node/pwsh。
2. **规划**：超过 100 行的任务拆成多文件（主逻辑/工具函数/README），单文件小工具就直接一个文件。文件名即功能名。
3. **编写**：中文注释只写「为什么」不写「是什么」；顶栏写用法示例（怎么运行、参数含义）。
4. **验证（必须）**：写完立即用 node/pwsh 跑一遍。有参数的用示例参数跑；跑不通就修到通，或如实报告卡在哪。
5. **交付说明**：答复里写三件事——文件路径、运行命令（可直接复制的完整命令行）、验证时的真实输出。

## 套路库
- 批量处理文件：pwsh `Get-ChildItem -Recurse -Filter *.ext | ForEach-Object { … }`，加 `-WhatIf` 预演再实跑。
- 网络请求：node 用内置 fetch，不引第三方依赖（用户环境 npm 装包要走镜像，别给用户添麻烦）。
- 定时任务：给出「如何挂到任务计划程序」的一行命令，不自动注册。
- 输出报告类：优先写 Markdown（用户能直接看），数据量大再上 CSV。

## 红线
- 不写需要管理员权限的脚本；确需提权时在答复里说明并给手动步骤。
- 不引入 node_modules 依赖；单文件自包含优先。
- 不改用户系统配置（注册表/服务/启动项），只交付文件和运行命令。
